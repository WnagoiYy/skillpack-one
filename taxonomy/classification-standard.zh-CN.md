# 能力分类标准

分类依据是用户要求的结果，而不是仓库名、作者或眼前可用的工具。

## 决策顺序

1. 找出最终要留下的产物或状态变化。
2. 选择对该产物正确性负责的领域。
3. 把生命周期、模态、依赖和风险记录为次级维度。
4. 用候选分类的排除条件与边界案例反向检查。
5. 在领先分类中，根据正向触发、能力契约与负向边界排列原子 Skill。
6. 若领先分类仍然接近，保留歧义并返回候选，不强行假装确定。

## 边界规则

- 一个领域可以复用另一个领域索引的原子能力，不因此取得其所有权。
- 产品名是依赖或标签，不是一级分类。
- 含多个可独立复用结果的流程属于能力包，不属于原子 Skill。
- 当安全或信任属性决定成功与否时，`security-trust` 优先负责。
- 改进 Skill、Agent、MCP 或 Harness 属于 `skill-agent-governance`；正常使用它们仍属于任务领域。
- 重新分类只改变索引，不改变稳定能力 ID。

## 统一描述档案

- 每个第一方分类、原子和元 Skill 都遵循同一套可移植 `SKILL.md` 结构和同一份机器可读 `skill.contract.yaml` Schema。
- `SKILL.md` 负责宿主发现和渐进式指令；能力契约负责能力身份、输入输出、权限、来源、路由边界与评测责任。
- 本地化索引可以调整术语和案例，但必须指向相同的稳定能力 ID 与权限边界。

## 层级与索引

- 分类树以结果为依据，深度不得超过 `taxonomy.maxDepth`；本实现最多三层分类。原子 Skill 是叶节点，不计入分类深度。
- 每个 taxonomy 节点都对应一个分类 Skill。生成的 `references/index.md` 是英文回退版本，同时提供 `index.en.md`、`index.zh-CN.md` 和 `index.zh.md`。
- 父分类索引先列出直接子分类，再列出本层原子能力。每次只向下读取一层索引，不能把整个子树一次性加载进上下文。
- 物理嵌套目录不是强制要求。本实现为兼容 Codex 发现机制而保持可执行 Skill 目录扁平，通过 taxonomy 父子关系和生成索引表达逻辑层级。

## 原子性检查

原子能力只有一个主要结果、一个主导产物或状态变化、一个权限包络、一个聚焦评分标准和一个独立失败边界。只有拆出的每一部分仍可独立复用时才拆分。

## 分类进化

只有版本化评测数据持续显示路由混淆、分类过载或新的正确性边界时，才允许拆分或合并分类。每次变更都要有迁移说明、重建索引、留出路由测试和回滚指针。

元 Skill 可以管理整个注册表、某个分类子树或单个 Skill。管理范围可以不同，但评测与回滚要求不能降低。
