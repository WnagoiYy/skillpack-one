# Skill 生命周期安全审查

可复用能力在产生实际效果之前会跨越多个信任边界。SkillPack One 分别审查这些边界，不把某个扫描器、签名或模型判断当作通用安全结论。

| 阶段 | 信任假设 | 代表性检查 |
| --- | --- | --- |
| 创作 | 描述、实际行为和所需权限一致。 | 隐藏指令、权限膨胀、不安全工作流 |
| 存储 | 准入后的产物保持真实、完整且版本正确。 | 来源、摘要、版本链、回滚、依赖 |
| 检索 | 恶意候选不能只靠操纵排序进入上下文。 | 关键词堆砌、语义伪装、Sybil 重复、触发词投毒 |
| 选择 | Planner 可见元数据忠实表达行为和权限。 | 虚假背书、误导描述、提示注入、权限不一致 |
| 执行 | 每个操作都处于运行时授权和信息流策略内。 | 未授权工具、不安全组合、敏感数据外发、提权 |
| 进化 | 更新继续保持来源、边界和受保护行为。 | 权限升级、指令注入、依赖变更、发布者被盗用 |

审查产物遵循 [`schemas/lifecycle-security-review.schema.json`](../../schemas/lifecycle-security-review.schema.json)，可运行：

```sh
npm run skillpack -- security check path/to/review.yaml
```

每个适用阶段都必须列出已考虑威胁、可追溯证据和残余风险；`not-applicable` 必须说明原因。新版本重新进入生命周期，不能自动继承旧版本信任。

通过审查仍不是充分条件：语义一致不等于运行时授权，签名不证明行为良性，检索过滤不能替代 Planner 校验，运行时 Guard 也可能遗漏模型改写产生的隐式信息流。
